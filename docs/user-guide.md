# Руководство пользователя (Шаг 5.3, черновик)

**Статус: черновик AI, план сам относит эту часть к «BIM + AI (черновики)»
(Шаг 5.3).** Видеоинструкции и реальное обучение групп пользователей —
честно вне AI-сессии, нужны живые люди и записанный экран. Этот документ
описывает только то, что реально работает и проверено тестами на сегодняшний
день (Шаги 1.3, 1.9, 2.12, 4.10, 4.11) — не выдуманный, а не написанный
заранее сценарий для функциональности, которой ещё нет в API.

## 1. Кто это читает

Проектировщик или сотрудник заказчика, который хочет получить BIM-модель
окружения участка (рельеф, здания, дороги, инженерные сети — в пределах
уже реализованных шагов) без ручной сборки подосновы. Взаимодействие — через
браузер (публичная карта города, встроенный 3D-просмотрщик) и/или напрямую
через REST API (для интеграции со своими инструментами).

## 2. Публичная карта города

Открыть `/citymap/index.html` (см. `docs/citymap.md`). Карта — MapLibre GL
поверх векторных тайлов OSM (здания, дороги по классам, вода, зелень,
ЛЭП), 2D/3D переключение, клик по объекту показывает карточку с его
атрибутами. Источники и лицензии (OpenStreetMap/OpenMapTiles) подписаны на
самой карте.

Кнопка **«Построить модель участка здесь»** на карте отправляет запрос в
сервис генерации модели (см. ниже) с центром в выбранной точке — самый
короткий путь от «нашёл место на карте» до готовой модели.

## 3. Регистрация и вход

- `POST /auth/register` — email + пароль, роль по умолчанию — «просмотр».
- `POST /auth/login` — возвращает токен сессии (`Bearer`-токен, 24 ч).
- `POST /auth/logout` — отзывает токен немедленно (не нужно ждать истечения
  срока).
- `GET /auth/me` — проверить, под каким пользователем и с какой ролью вы
  вошли.

Роли (буквально по плану): «просмотр», «проектировщик», «администратор».
Повышение роли и выдачу права «доступ к закрытому контуру» (сети,
изыскания) делает администратор через панель управления пользователями
(см. `docs/admin-guide.md`) — самостоятельно повысить себе роль нельзя.

## 4. Создание модели участка

1. `POST /jobs` с телом:
   ```json
   {"center": {"lon": 56.25, "lat": 58.02}, "radius_m": 750,
    "layers": [], "detail": "LOD2"}
   ```
   Заголовок `Authorization: Bearer <токен>` — необязателен: без него
   задача анонимная (не появится в «Мои проекты», но выполнится так же).
   `radius_m` — от 500 до 3000 м. Координаты должны попадать в зону
   МСК-59 (Пермский край) — иначе понятная ошибка сразу, без постановки в
   очередь.
2. `GET /jobs/{id}` — статус и прогресс по шагам конвейера (импорт OSM,
   рельеф, выборка/нормализация, сборка IFC, конвертация в GLB). Опрашивать
   раз в 1-2 секунды до терминального статуса (`done`/`failed`).
3. `GET /models/{id}/files` — список готовых файлов с `download_url` на
   каждый и `viewer_url` на GLB. Готовые файлы появляются по мере
   завершения шагов, не только по готовности всей задачи целиком.
4. Открыть `viewer_url` — встроенный 3D-просмотрщик (дерево объектов по
   слоям, панель свойств по клику на объект).

Если у вас есть сессия (вошли через `/auth/login`), задача автоматически
привязывается к вам и появляется в `GET /projects` («Мои проекты» в
будущем личном кабинете).

## 5. Уведомления

Когда задача завершается (успешно или с ошибкой), уведомление появляется в
`GET /me/notifications`. Промежуточные шаги не уведомляют — только
завершение целиком (нет готового канала push-доставки вроде WebSocket,
опрос `GET /jobs/{id}` — единственный способ следить за прогрессом «вживую»).

## 6. Публичные ссылки на модель

`POST /jobs/{job_id}/share` (только владелец задачи) создаёт отзываемую
ссылку. `GET /public/{token}` открывает 3D-просмотрщик без авторизации —
удобно для показа модели коллегам без учётной записи. Отозвать ссылку
может только владелец задачи (эндпоинт отзыва — там же, где создание).

## 7. Доступ к закрытому контуру

Если вам выдано право «доступ к закрытому контуру» (выдаётся
администратором отдельно от роли), `GET /projects/{job_id}/closed-contour`
покажет официальные ограничения по участку задачи (ЗОУИТ, СЗЗ,
водоохранные зоны и т. п., см. `docs/constraints.md`) — то, что скрыто от
пользователей без этого права (403).

## 8. Экспорт в Pilot-BIM

`POST /jobs/{id}/export-to-pilot-bim` копирует готовые `.ifc`-файлы задачи
в папку обмена Pilot-BIM (настраивается администратором,
`PILOT_BIM_EXCHANGE_DIR`). Прямая интеграция через API Pilot-BIM не
реализована — платформа проприетарная, нужна лицензия и доступ заказчика
(см. `docs/dashboard.md`).

## 9. Внешний API (для интеграторов)

- Документация: `GET /docs` (Swagger UI) или `GET /openapi.json` — всегда
  актуальны, генерируются автоматически из кода.
- Ключи доступа: `X-API-Key: <ключ>` — альтернатива токену сессии для
  скриптов/интеграций, выдаёт администратор.
- Вебхуки о готовности задачи — регистрируются администратором или
  владельцем интеграции, доставка — настоящий HTTP POST при переходе
  задачи в `done`/`failed`.

## 10. Честно: чего в этом руководстве пока нет

- **Посадка ЖК на конкретный участок, подбор ограничений под конкретный
  проект, формирование пакета запросов на технические условия** (Шаги
  3.6-3.12 плана) — эта часть конвейера реализована и протестирована
  (`docs/siting.md`, `docs/rso.md`, `docs/constraints.md`), но пока
  доступна только как библиотека Python/через код, НЕ через REST API или
  личный кабинет — значит, пользователю-не-разработчику пока
  недоступна напрямую. Обёртка этих функций в эндпоинты — отдельная,
  ещё не выполненная работа; когда она появится, этот раздел руководства
  будет дописан.
- **Личный кабинет как отдельная веб-страница** (список проектов, история,
  кнопки в интерфейсе, а не «руками» через `curl`/Swagger) — сейчас есть
  только backend API Шага 4.10, самой страницы (аналог `/citymap` или
  `/viewer`) не построено.
- **Рендеры и панорамы** (Шаги 4.1-4.7) — генерируются через
  Celery-воркер (`docs/rendering.md`), но постановка такой задачи для
  конкретной модели не подключена к `POST /jobs`/личному кабинету —
  сейчас это отдельный внутренний процесс, не самостоятельный пользовательский
  сценарий «нажал кнопку — получил рендер».
- Видеоинструкции и очное обучение — вне AI-сессии, нужны люди и запись
  экрана.

# Электросети с опорами (Шаг 2.7)

`osm2pgsql` (Шаг 1.1) уже собирает `power=tower/pole/substation` (точки),
`power=line/minor_line` (линии) и `power=substation/plant` (полигоны, если
контур замкнут) в одну таблицу `osm_power` — изменений импорта для этого
шага не потребовалось. `voltage=*` уже нормализуется в кВ на выборке (Шаг
1.4, `selection.normalize.normalize_power`); Шаг 2.7 переиспользует
`feature.attributes["voltage_kv"]`, а не разбирает тег заново.

## Опоры/башни по типовым сериям (п. 1)

`geometry.power.build_poles` — по факту точки OSM (`power=tower`/`power=
pole`). Форма зависит от типа, не от параметрической серии конкретного
производителя (для этого нет данных в OSM):

- `power=pole` — простой столб ПОСТОЯННОГО сечения; радиус — по тегу
  `material` (`wood`/`concrete`/`steel`), умолчание `wood`.
- `power=tower` — решётчатая опора, упрощённо СУЖАЮЩИЙСЯ К ВЕРШИНЕ силуэт
  (`mesh_cylinder(radius_top=...)`, новый параметр этого шага), БЕЗ
  реальных ферм/раскосов — тот же уровень детализации, что у опор
  контактной сети (Шаг 2.6).

Высота — тег `height`, при отсутствии типовое значение по категории (столб/
башня). `Pset_ЛЭП.Серия` — тег `design`/`structure` КАК ЕСТЬ, если был;
при отсутствии свойство не подставляется (не изобретается конкретная
серия/каталожный номер — в OSM их не бывает).

## Опоры по точкам, расчётная расстановка при отсутствии (п. 2)

`geometry.power.place_calculated_poles` — расчётная расстановка ТОЛЬКО для
линий (`power=line/minor_line`), у которых нет НИ ОДНОЙ реальной опоры в
пределах `POLE_SNAP_DISTANCE_M` (3 м) от оси; если хотя бы одна найдена,
линия считается обеспеченной реальными точками. Опоры распределены РАВНОМЕРНО
по всей длине линии с шагом, близким к `CALCULATED_POLE_SPACING_M` (60 м,
типовой пролёт ВЛ), без обрубка последнего пролёта. Помечены честно —
`Pset_ЛЭП.Источник="умолчание"`, реальные — `"факт"`.

## Провода цепной линией (п. 3)

`geometry.power.build_wire_spans` — для каждой линии находит опоры (реальные
+ расчётные вперемешку), лежащие в пределах допуска от её оси, упорядочивает
по проекции на ось и строит провод между КАЖДОЙ последовательной парой.

Провис — ПАРАБОЛИЧЕСКОЕ приближение цепной линии (`SAG_RATIO=3%` длины
пролёта): стандартный инженерный приём при малом провисе относительно
пролёта, используется в реальном проектировании ВЛ, а не точное
гиперболическое решение и не расчёт по натяжению/температуре/гололёду.
Минимум провиса геометрически на середине пролёта — упрощение (в физически
точной цепной линии при разных отметках опор минимум смещён к более низкой).

Число проводов — тег `cables` (все провода как есть, включая возможный трос
грозозащиты), умолчание 3 (одна цепь, 3 фазы). Провода разнесены по
горизонтали одним рядом на `PHASE_SPACING_M` (1,5 м) — упрощённо, без
треугольной/вертикальной раскладки траверс реальной опоры.

Геометрически провод — не круглая труба, а тонкая ПЛОСКАЯ ЛЕНТА вдоль
сэмплированной 3D-ломаной (`ifc.assemble.mesh_ribbon_along_path`), «стоящая
на ребре»: смещение только по горизонтальному перпендикуляру к локальному
направлению, вертикальная составляющая (сам провис) в ширину не
проецируется. Тот же общий приём, что и у плоских лент дороги/воды/балласта
(`line.buffer(width/2)`), только с индивидуальной отметкой каждой точки пути
вместо одной общей плоскости.

Собран как `IfcCableSegment`/`CABLESEGMENT` (НЕ `IfcFlowSegment` — эта
проверено эмпирически через ifcopenshell не имеет собственного
`PredefinedType` в IFC4/IFC4X3 вовсе, только конкретные подтипы вроде
`IfcCableSegment`; ранняя запись Шага 0.8 `IfcFlowSegment`/`CABLE` в
`docs/data-dictionary.md` была неверной, исправлена этим шагом), нативно в
обеих схемах — без прокси-ветвления, как у `IfcRoad`/`IfcBridge`.

## Подстанции и ТП упрощёнными объёмами (п. 4)

`geometry.power.build_substations` — только оконтуренные (`power=
substation`/`plant`, полигон); точечная подстанция (только позиция, без
контура площадки в OSM) объёма не имеет и честно пропускается, размер не
изобретается. Высота — единая типовая `SUBSTATION_HEIGHT_M` (4 м), низ —
минимум рельефа по контуру (тот же принцип, что `level_z` у компактного
водоёма, Шаг 1.7).

## Охранная зона по классу напряжения (п. 5)

`geometry.power.build_power_safety_zones` — буфер вокруг оси линии на
полуширину по классу напряжения (`voltage_kv`, уже нормализован). Реальные
нормативные значения (не выдуманные):

| Класс напряжения | Полуширина | Источник |
| --- | --- | --- |
| до 1 кВ | 2 м | ПП РФ №160 от 24.02.2009 |
| 1–20 кВ | 10 м | |
| 35 кВ | 15 м | |
| 110 кВ | 20 м | |
| 150, 220 кВ | 25 м | |
| 330, 500, ±400 кВ | 30 м | |
| 750, ±750 кВ | 40 м | |
| 1150 кВ | 55 м | |

Без тега `voltage` класс не определить — зона честно НЕ строится (тот же
принцип, что у проверки габарита моста без осей пересекаемых объектов, Шаг
2.5, п. 3: не гадаем норматив вместо отсутствующих данных).

Представлена как `IfcSpatialZone`/`Pset_Ограничение` (та же схема, что
запланирована для официальных ЗОУИТ Шага 3.1) с `Вид="охранная зона ЛЭП"`,
`Статус="расчётная"` — честно, это калькуляция по нормативу, а не сверка с
официальным реестром (Шаг 3.1 этим проходом не реализован). Объём —
представительная высота `SAFETY_ZONE_HEIGHT_M` (25 м, типовое значение с
запасом выше большинства опор распределительных и низких магистральных
классов), НЕ выведена из фактических опор конкретной линии.

`IfcSpatialZone` — `IfcSpatialElement`, роднится с сайтом через
`aggregate.assign_object` (как `IfcRoad`/`IfcBridge`), а не
`spatial.assign_container` — та ожидает `ContainedInStructure`, которого у
пространственных элементов нет (проверено эмпирически: `ifcopenshell.api.
spatial.assign_container` падает на `IfcSpatialZone` с `AttributeError`).

## Что НЕ входит в этот проход (сознательно, честно, не обещано)

- **Реальные фермы/раскосы решётчатой башни, траверсы, изоляторы** — башня
  упрощена до сужающегося конуса-оболочки, без внутренней конструкции.
- **Бандл-провода (расщеплённая фаза на высоких классах напряжения)** —
  один провод на фазу.
- **Смещение минимума провиса к более низкой опоре** при разных отметках —
  симметричная парабола.
- **Расчёт провиса по натяжению/температуре/гололёду** — единый типовой
  процент от длины пролёта для всех классов напряжения.
- **Сверка охранной зоны с официальным реестром (НСПД)** — критерий
  проверки шага по плану («зоны совпадают с НСПД там, где они есть»)
  недоступен AI-сессии без реального доступа к реестру; зона в этом проходе
  — целиком расчётная.
- Проверка на реальных линиях пилота (критерий шага по плану) — недоступна
  AI-сессии без пилотного участка (Шаг 0.1).

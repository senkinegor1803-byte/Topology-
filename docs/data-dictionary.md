# Словарь данных (Шаг 0.8)

Статус: **черновик v0.1**, покрывает объём Этапа 1 (MVP 500 м) и основу для
Этапа 2–3. Требует сверки с BIM-специалистом (критерий приёмки Шага 0.8) —
AI-сессия подготовила таблицу, подтверждение того, что она покрывает задачи
проектирования, остаётся за BIM-специалистом.

Соглашение по именованию: пользовательские Pset — с приставкой `Pset_` и
русским названием (кириллица), как в тестовом генераторе IFC
(`geo/src/topology_geo/ifc/generate_test_ifc.py`, Шаг 0.2). Общие для всех
объектов: `Pset_Контекст` (что и зачем сгенерировано), `Pset_Источник` (откуда
данные и когда), `Pset_Ограничение` (если объект — зона/ограничение).

## 1. Классы IFC по типам объектов

| Тип объекта | Класс IFC | PredefinedType | Специфичный Pset | Ед. изм. |
| --- | --- | --- | --- | --- |
| Рельеф (TIN) | `IfcGeographicElement` | `TERRAIN` | `Pset_Рельеф` (Источник_DEM, Дата, Погрешность_м) | м |
| Здание (упрощённо, Этап 1) | `IfcBuildingElementProxy` | `USERDEFINED` | `Pset_Здание` (Тип, Высота_м, Источник_высоты: OSM/Overture/тип (умолчание)) | м |
| Здание LOD2 (Этап 2 — Шаг 2.2) | `IfcBuildingElementProxy` (стены+крыша один солид на контур/часть) | `USERDEFINED` | `Pset_Здание` (как в Этапе 1, плюс Входов_всего/Вход_N_Тип/Вход_N_X_м/Вход_N_Y_м — Шаг 2.2, п. 1/3), `Pset_Крыша` (Форма, Высота_конька_м, Источник_высоты, Направление_град — только для скатной/односкатной; нет для flat), `Pset_Контекст.Часть_здания=true` для `building:part` | м |
| Дорога, каркасная сеть | `IfcRoad` (IFC 4.3) / `IfcBuildingElementProxy`-прокси (IFC4) | по классу (`MOTORWAY`…`RESIDENTIAL` где применимо) | `Pset_Дорога` (Класс, Покрытие, Полосы, Ширина_м, Статус: официальная/расчётная) | м |
| Полоса (Этап 2 — Шаг 2.3, п. 1, через osm2streets) | `IfcBuildingElementProxy` | `USERDEFINED` | `Pset_Полоса` (Тип: Driving/Sidewalk/Parking/…, Ширина_м, Направление: Fwd/Back) | м |
| Перекрёсток / угол тротуара (Шаг 2.3, п. 1) | `IfcBuildingElementProxy` | `USERDEFINED` | `Pset_Перекрёсток` (Тип) | м |
| Дворовой проезд | `IfcRoad`/прокси, помечается отдельно | `USERDEFINED` | `Pset_Дорога` + `Редактируемый=true` | м |
| Мост / путепровод | `IfcBridge` (IFC 4.3) / прокси (IFC4) | `USERDEFINED` | `Pset_Мост` (Габарит_м, Статус: официальный/расчётный) | м |
| Вода (полигон, лента) | `IfcGeographicElement` | `USERDEFINED` | `Pset_Вода` (Тип: река/ручей/водоём, Источник) | м |
| Ж/д, трамвай | `IfcRail`(IFC4.3)/прокси | `USERDEFINED` | `Pset_ЖД` (Число_путей, Ширина_колеи_мм) | мм |
| Дерево | `IfcGeographicElement` | `USERDEFINED` | `Pset_Растительность` (Порода, Высота_м, Источник: факт/умолчание) | м |
| ЛЭП — опора | `IfcBuildingElementProxy` (параметрич.) | `USERDEFINED` | `Pset_ЛЭП` (Напряжение_кВ, Материал, Серия) | кВ |
| ЛЭП — провод | `IfcFlowSegment` | `CABLE` | `Pset_ЛЭП` (Напряжение_кВ, Число_фаз, Число_цепей) | кВ |
| Охранная/санитарная зона | `IfcSpatialZone` | `USERDEFINED` | `Pset_Ограничение` (Вид, Статус: официально/расчётно, Реестровый_номер, Документ) | — |
| Подземная сеть (труба, кабель) | `IfcPipeSegment` / `IfcCableSegment` | по типу сети (К1/В1/Т1/Г…) | `Pset_Сеть` (Диаметр_мм, Материал, Глубина_м, Источник_отметки: факт/нормативная) | мм, м |
| Колодец | `IfcBuildingElementProxy` | `USERDEFINED` | `Pset_Сеть` | — |
| ЗОУИТ / ПЗЗ / красная линия | `IfcSpatialZone` | по виду | `Pset_Ограничение` | — |
| ЖК (импорт из Renga) | как в исходном IFC | — | добавляется `Pset_Контекст.Источник=Renga` | — |

## 2. Соответствие тегов OSM → свойств

| Тег OSM | Свойство в Pset | Правило |
| --- | --- | --- |
| `building:levels=5` | `Pset_Здание.Высота_м` | `Этажность * 3 + 1`, если нет `height`; `Источник_высоты="OSM"` |
| `height=17.5` | `Pset_Здание.Высота_м` | как есть (приоритет над `building:levels`); `Источник_высоты="OSM"` |
| `building=*` (без height/levels) | `Pset_Здание.Источник_высоты` | Overture, если доступен (Шаг 2.2, п. 2), иначе `"тип (умолчание)"` по справочнику типов |
| `roof:shape=gabled/hipped/pyramidal/skillion` | `Pset_Крыша.Форма` | как есть; прочие значения (dome, mansard…) → плоская крыша (упрощение, Шаг 2.2) |
| `roof:height=3.5` | `Pset_Крыша.Высота_конька_м` | как есть; иначе по `roof:angle` или дефолту 30° |
| `roof:direction=135` | `Pset_Крыша.Направление_град` | компас, вниз по скату (только skillion; для gabled определяет ориентацию конька) |
| `building:part=*` (полигон внутри контура `building=*`) | отдельный `IfcBuildingElementProxy` со своим `Pset_Здание`/`Pset_Крыша`, `Pset_Контекст.Часть_здания=true` | пространственное сопоставление с контуром (`shapely.intersects`, Шаг 2.2, п. 1); контур, пересекающий хотя бы одну часть, сам не экструдируется (вики Key:building:part) |
| `entrance=yes/main/staircase/exit/…` (точка) | `Pset_Здание.Входов_всего`, `Вход_N_Тип`, `Вход_N_X_м`, `Вход_N_Y_м` | точка сопоставляется зданию/части, если лежит в его контуре с запасом 1 м (Шаг 2.2, п. 3); без новой геометрии |
| `surface=asphalt` | `Pset_Дорога.Покрытие` | как есть (словарь допустимых значений — Приложение A) |
| `lanes=2` | `Pset_Дорога.Полосы` | как есть, число |
| `highway=*`, `lanes=*`, `sidewalk=*`, `parking:*` + связность узлов (`osm_roads.nodes`, Шаг 1.1) | `Pset_Полоса.Тип/Ширина_м/Направление` на каждую полосу | через реальный osm2streets (Шаг 2.3, п. 1, `geometry/streets.py`), не переразбор тегов на Python — источник истины типов полос и их геометрии остаётся у инструмента |
| `highway=motorway…tertiary` | `Pset_Дорога.Класс` = «каркасная» | см. Шаг 2.4 |
| `highway=residential/service/living_street/footway…` | `Pset_Дорога.Класс` = «внутриквартальная» | см. Шаг 2.4 |
| `voltage=15000` | `Pset_ЛЭП.Напряжение_кВ` | деление на 1000: `15000 → 15` |
| `power=tower` / `power=pole` | класс `IfcBuildingElementProxy`, `Pset_ЛЭП.Материал` | по `design`/`structure` |
| `species=Betula pendula` / `leaf_type` | `Pset_Растительность.Порода` | как есть; при отсутствии — «умолчание» по типу массива |
| `waterway=stream/river` | `Pset_Вода.Тип` | как есть |
| `railway=rail/tram` | `Pset_ЖД.Число_путей` | подсчёт параллельных путей |
| `operator=*` | `Pset_Сеть.Организация` (Шаг 3.10) | как есть, далее сверяется со справочником РСО |

Полный словарь допустимых значений тегов и их русских эквивалентов —
Приложение A (заполняется по мере реализации генераторов Этапа 1–2, не
дублируется здесь заранее).

## 4. Структура файлов федеративной модели

Один IFC-файл на слой/кольцо (Шаг 2.10), имена файлов — по шаблону
`<task_id>_<layer>_<lod>.ifc`:

| Файл | Содержимое |
| --- | --- |
| `relief.ifc` | Рельеф (TIN), сшитый по всем кольцам |
| `roads_backbone.ifc` | Каркасная дорожная сеть (нередактируемая) |
| `roads_local.ifc` | Внутриквартальная сеть (параметрическая) |
| `buildings_lod{0,1,2}.ifc` | Здания окружения по кольцам детализации |
| `power.ifc` | ЛЭП, опоры, подстанции, охранные зоны |
| `networks.ifc` | Подземные сети (закрытый контур, права доступа) |
| `constraints.ifc` | ЗОУИТ, ПЗЗ, красные линии, ОКН, ООПТ |
| `vegetation.ifc` | Деревья, благоустройство |
| `site_<project>.ifc` | Посаженный ЖК + пятно застройки (Этап 3) |
| `meta.json` | Метаданные пакета — схема `schemas/meta.schema.json` |

## 5. Как обновлять

Правки в словарь вносятся в том же коммите, что и код генератора, который на
него опирается; расхождение словаря и кода — повод исправить один из них.

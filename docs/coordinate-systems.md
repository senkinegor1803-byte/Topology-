# Системы координат проекта (Шаг 0.4)

Статус: **черновик / рабочее приближение**. Официальные параметры МСК-59 и
контрольные точки для калибровки высот — задача организационная (нужен
официальный документ Росреестра/Управления Роскадастра по Пермскому краю и
данные топосъёмки от изыскателя, роль ИЗ в `docs/plan.md`). Этот документ и
модуль `geo/src/topology_geo/coords.py` дают рабочий код и функции проверки,
которые нужно прогнать на реальных данных, когда они появятся.

## Плановые системы

| Назначение | Система | Комментарий |
| --- | --- | --- |
| Источник плана (OSM) | WGS-84 (EPSG:4326) | географические координаты |
| Проектная плоская система | МСК-59 | Пермский край, 3 трёхградусные зоны, эллипсоид Красовского |
| Высоты топосъёмки / изысканий | Балтийская система | нормальные высоты |
| Высоты TessaDEM | EGM96 | приближённо эллипсоидальные для наших целей |

## Параметры МСК-59 (рабочее приближение)

Параметры ниже — расчётные по ГОСТ Р 51794-2008, как их публикуют геодезические
справочники и производители ГИС. Использованы источники:

- https://mapbasic.ru/msk59
- https://terraingis.ru/msk-59.html

| Зона | Осевой меридиан | X0 (false easting), м | Y0 (false northing), м |
| --- | --- | --- | --- |
| 1 | 53.55° | 1 250 000 | −5 914 743.504 |
| 2 | 56.55° | 2 250 000 | −5 914 743.504 |
| 3 | 59.55° | 3 250 000 | −5 914 743.504 |

Эллипсоид: Красовского. 7-параметрический сдвиг Красовский → WGS-84 (towgs84,
формат PROJ dx,dy,dz,rx,ry,rz,ds[ppm]): `23.57, -140.95, -79.8, 0, 0.35, 0.79, -0.22`.

Пилотный участок в Перми (центр города, долгота ≈ 56.2–56.3°) попадает в
**зону 2** (осевой меридиан 56.55°).

**Не подтверждено официальным документом.** Прежде чем использовать в проде —
получить официальные параметры (Шаг 0.4, п. 1) и прогнать
`topology_geo.coords.verify_planimetric` на реальных пунктах ГГС.

## Высоты: EGM96 → Балтийская система

Разница между эллипсоидальной высотой EGM96 и нормальной высотой в Балтийской
системе — не константа, она зависит от точки (уклонение геоида). Правильный
способ — грид EGM96 через PROJ (`+proj=vgridshift`), но в этой изолированной
среде разработки грид недоступен ни локально, ни по сети (см. попытку в истории
разработки: `pyproj.network` не может достучаться до CDN PROJ отсюда). Поэтому
`coords.py` реализует практический путь, который и так требуется по Шагу 0.4:
локальная калибровка по контрольным точкам (`fit_height_offset` — константа для
1–2 точек, наклонная плоскость МНК для ≥3 точек), с проверкой
(`verify_heights`) по критерию ≤ 0.05 м.

**Что нужно сделать вживую (не AI):** получить 5–10 контрольных точек с
известной высотой в обеих системах (пункты ГГС, углы зданий из топосъёмки),
прогнать `fit_height_offset` + `verify_heights`, зафиксировать результат в этом
документе.

## Базовая точка проекта

Правило (по Шагу 0.4, п. 4) фиксируется здесь после выбора пилотного участка
(Шаг 0.1): одна базовая точка (lon, lat, зона МСК-59, координаты X/Y, высота)
хранится в служебной таблице PostGIS и передаётся в каждый IFC через
`IfcMapConversion` (см. `geo/src/topology_geo/ifc/generate_test_ifc.py`).
Пока пилотный участок не выбран, генератор IFC использует условную точку
рядом с центром Перми — заменить на реальную после Шага 0.1.

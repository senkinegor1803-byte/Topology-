# Промышленная инфраструктура (Шаг 5.1)

`infra/docker-compose.prod.yml` (надстройка) + `infra/Caddyfile` +
`infra/monitoring/{prometheus,alerts}.yml` + `infra/backup/*.sh`.

## Разделение контуров (п. 1)

Развёртывание реальных серверов (п. 1: «серверы по п. 10.2 ТЗ или
облачные аналоги», разделение открытого/закрытого контуров) —
**честно вне AI-сессии**: нет облачных учётных данных/биллинга, нет
реального домена/DNS. Программная часть разделения контуров готова с
Шага 4.10 (`closed_contour_access` — реальный гейт на данные сетей/
изысканий, Шаг 3.1); физическое разделение на уровне сети/серверов —
организационное решение заказчика при развёртывании.

## HTTPS (п. 2)

`infra/Caddyfile` + сервис `caddy` в `docker-compose.prod.yml` —
реальный, широко используемый reverse-proxy с автоматическим выпуском
и продлением сертификатов Let's Encrypt (протокол ACME), не
самоподписанный сертификат. Домен подставляется переменной
`TOPOLOGY_DOMAIN` при запуске — без неё `docker compose config`
честно падает (`:?` в определении сервиса), проверено реально (exit
code 1 без переменной, 0 с ней).

## Мониторинг и оповещения (п. 2)

`infra/monitoring/prometheus.yml` — Prometheus, `scrape_interval: 30s`,
цели: FastAPI (`/metrics`), `postgres_exporter`, `redis_exporter`,
сам Prometheus. `infra/monitoring/alerts.yml` — правило `ServiceDown`
(`up == 0`, `for: 2m`) на встроенной метрике Prometheus (появляется
автоматически для любой цели `scrape_configs`, не требует кода
приложения) — интервал опроса + `for` дают срабатывание максимум через
~2.5 мин с момента отказа, с запасом укладывается в критерий шага
(«≤ 5 мин»). Плюс `PostgresDown` (специфично для БД) и `DiskSpaceLow`
(предупреждение о нехватке места — резервные копии/растровые данные
не поместятся; метрики берутся с сервиса `node-exporter`, добавленного
в `docker-compose.prod.yml` специально под это правило). Grafana — визуализация поверх тех же метрик Prometheus
(дашборды не поставляются в этом проходе — типовые дашборды для
`postgres_exporter`/`redis_exporter`/FastAPI есть в публичной галерее
Grafana, подключаются по ID при первом запуске).

**Честно не реализовано:** сама точка `/metrics` в `api/app.py` —
подключение ASGI-мидлваря Prometheus (`prometheus-fastapi-instrumentator`
или аналог) не входит в этот проход (Шаг 5.1 — инфраструктура
эксплуатации, конфигурация её потребителя; добавление мидлваря в само
приложение — отдельная, небольшая доработка кода `api/app.py`).

## Резервное копирование и восстановление (п. 3)

**PostgreSQL — реально написано И реально проверено.**
`infra/backup/backup_postgres.sh` — `pg_dump --format=custom
--compress=9` (сжатый, поддерживает параллельное восстановление, не
текстовый SQL-дамп). `infra/backup/restore_postgres.sh` — пересоздаёт
целевую БД (`DROP DATABASE ... WITH (FORCE)` + `CREATE DATABASE`,
расширение PostGIS) и восстанавливает через `pg_restore --jobs=$(nproc)`
(параллельно, не однопоточно). Оба скрипта реально вызваны как
настоящие subprocess'ы (не переписаны в Python) в
`geo/tests/test_ops_backup_restore.py` — реальная репетиция
восстановления: настоящие данные (пользователь + задача с реальными
полями) → `pg_dump` → НОВАЯ база данных → `pg_restore` → сверка полей
восстановленных записей с исходными. На тестовом объёме данных backup
занял 0.20 с, restore — 1.29 с; критерий шага («учебное восстановление
≤ 4 ч») сформулирован для промышленного объёма данных реального
пилота — здесь честно подтверждён работающий МЕХАНИЗМ, не время на
проде, которого не существует без пилота (Шаг 0.1).

**MinIO — написано, НЕ проверено.** `infra/backup/backup_minio.sh`
(`mc mirror`, стандартный документированный приём самого MinIO) — в
этой среде нет ни запущенного MinIO (нет демона Docker), ни
установленного клиента `mc`, поэтому реального прогона не было. Честно
помечено прямо в самом скрипте.

## Тесты

`geo/tests/test_ops_backup_restore.py` — 3 теста, включая полную
репетицию backup→restore на реальном PostGIS. CI (`.github/workflows/
ci.yml`) теперь валидирует ОБА compose-файла — базовый и продуктивную
надстройку (`docker compose -f docker-compose.yml -f
docker-compose.prod.yml config` с плейсхолдер-переменными).

## Что не проверено

- Реальный прогон на сервере/в облаке (нет учётных данных/биллинга).
- Сборка/выпуск настоящего Let's Encrypt сертификата (нужен реальный
  домен с публичным DNS).
- Резервное копирование MinIO (см. выше).
- Реальные дашборды Grafana, реальная доставка оповещений (Slack/email/
  Telegram — канал доставки не выбран, зависит от предпочтений
  эксплуатирующей команды).

# Импорт подземных сетей из DXF (Шаг 3.4)

Реализация: `geo/src/topology_geo/networks/dxf_import.py`.

## Чтение DXF (п. 1)

Через `ezdxf` (уже зависимость проекта, Шаг 2.10 — там на запись
`export/dxf.py`, здесь на чтение). Нативный **DWG честно не читается** —
`ezdxf` понимает только DXF; конвертер DWG→DXF (ODA File Converter /
`libredwg`) в этой среде не установлен (`which dwg2dxf ODAFileConverter`
— пусто) и не может быть установлен без сети до его дистрибутива. Большинство
САПР умеют экспортировать DXF из DWG напрямую — организация, отдающая
топоплан (Шаг 0.3, не реализован в этой сессии), может сразу прислать DXF;
тот же класс честного ограничения, что и у остальных материалов проекта,
получаемых от третьих сторон.

## Сопоставление слоёв словарю (п. 2)

`match_layer_to_network_type(layer_name)` — сначала СТАНДАРТНЫЙ код слоя
(`К1`/`В2`/`Т1`/`Г`/`Кл`, с цифрой или без, регистронезависимо), затем
описательные русские/английские ключевые слова ЦЕЛЫМ СЛОВОМ (не подстрокой
— однобуквенный код «Г» подстрокой ловил бы что угодно). Несопоставленный
слой возвращает `None` и попадает в `DxfImportResult.unmatched_layers` —
честный сигнал «нужно подтверждение человека» (вторая часть действия
плана — «предложение соответствия (Claude) с подтверждением человеком»):
сама AI-сессия, работающая с реальным топопланом, может предложить
соответствие по контексту (в отличие от этого модуля, не видящего чертёж
целиком) — здесь заложен явный список несопоставленных слоёв для такого
шага, не тихая догадка вместо него.

## Диаметр/материал/отметка из подписей, колодцы из блоков (п. 3)

`extract_diameter_mm`/`extract_material`/`extract_elevation_m` — простые
регулярные выражения по типичным обозначениям топоплана (`Ø300`, `d=150`,
`D200`; материал — по словарю ключевых слов: сталь/чугун/ПНД/ПВХ/
железобетон/асбестоцемент; отметка — `отм.=95.50`/`z=-2.5`, поддержаны обе
десятичные записи — точка и запятая). Подпись сопоставляется ближайшей
линии/полилинии по расстоянию (`--snap-distance`, по умолчанию 5 м —
тот же приём, что снаппинг реальных опор ЛЭП к линии, Шаг 2.7). Колодцы —
блоки (`INSERT`), точки вставки + имя блока, БЕЗ попытки угадать тип
колодца по имени (это отдельная, не решённая здесь задача — имена блоков
в реальных топопланах не стандартизированы).

## 3D-трубопроводы, нормативная глубина (п. 4)

`NetworkSegment.elevation_m` — из подписи (`elevation_source="факт"`), а
при её отсутствии — честная нормативная глубина заложения по типу сети
(`NORMATIVE_DEPTH_M_BY_NETWORK_TYPE`, представительные значения СП
42.13330.2016 для средней полосы/Урала, `elevation_source="нормативная"`)
— ни одна труба не остаётся без Z, но источник высоты всегда виден.

**Честно не реализовано:** построение реального 3D-меша трубы/кабеля
(цилиндр/лента вдоль оси на найденной глубине) — модуль отдаёт готовые,
протестированные 2D-геометрию + атрибуты (диаметр/материал/отметка/
источник), но не собирает IFC/GLB-представление; естественное переиспользование
— `ifc.assemble.mesh_cylinder`/`mesh_ribbon_along_path` (те же хелперы, что
уже строят провода ЛЭП и ленты дорог/воды, Шаги 2.3/2.7), не сделано в этом
проходе, как и подключение к `jobs.steps`.

## Закрытый контур с правами доступа (п. 5)

**Честно не реализовано.** В проекте вообще нет системы
аутентификации/ролей (ни для одного слоя данных, не только подземных
сетей) — вводить её ради одного этого пункта означало бы либо неполноценную
имитацию прав доступа (хуже, чем прямо сказать «не сделано»), либо
отдельную большую подсистему вне объёма этого шага. `ObjectStorage` (Шаг
1.3) уже разделяет объекты по `job_id`-префиксу ключей (что не даёт одной
задаче скачать файлы другой, `test_download_rejects_key_belonging_to_a_
different_job`), но это не ролевой доступ, а изоляция задач друг от друга.

## Проверка (`docs/plan.md`)

«На пилоте ≥ 90% сетей топоплана перенесены с верным типом и диаметром» —
**не проверено**: нужен реальный топоплан пилотного участка (Шаг 0.1, не
реализован — требует физического выбора участка, недоступен AI-сессии).
Модуль реально протестирован на синтетическом, но структурно настоящем
DXF (собран и прочитан через тот же `ezdxf`, что и production-код, не
руками записанные байты) — 4 сегмента разных слоёв, 3 сопоставленных типа
сети + 1 честно несопоставленный, диаметр/материал/отметка из подписей,
нормативная глубина при отсутствии подписи, один колодец из блока.

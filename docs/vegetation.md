# Растительность и благоустройство (Шаг 2.9)

Базовые деревья (одиночные с породой/дефолтом, массив по плотности) — Шаг
1.7, п. 4, `geometry.vegetation`. Этот документ — уточнения Шага 2.9:
высота дерева, плотность массива по типу леса, газон отдельно от леса,
кустарник, скамейка. Ограждения/фонари — уже Шаг 2.8, см. `docs/asset-
library.md`.

## Высота дерева из `height` (действие «высотой из height»)

`build_individual_trees` парсит тег `height` (метры, как есть); при
отсутствии/некорректном значении — типовое `DEFAULT_TREE_HEIGHT_M=12 м`
(характерный взрослый экземпляр уличного/паркового дерева средней полосы,
не расчёт по породе/возрасту), confidence «умолчание». `TreePoint` хранит
`height_m`/`height_confidence` НЕЗАВИСИМО от `species`/`confidence` — порода
и высота дерева могут быть известны по отдельности (реальный OSM-объект
нередко тегируется `height` без `species`, и наоборот).

Рассеянные деревья леса/массива (`scatter_forest_trees`) высоты не имеют по
природе объекта (синтетические точки внутри полигона, не реальные OSM-точки
с собственным тегом) — используют то же типовое значение, confidence
всегда «умолчание».

## Плотность массива по типу леса (действие «рассеивание с плотностью по типу леса»)

Раньше (Шаг 1.7) — одна плоская плотность (`DEFAULT_FOREST_DENSITY_PER_HA=
400/га`) на любой полигон `osm_vegetation`. Теперь тег `leaf_type` полигона
леса (`natural=wood`/`landuse=forest`) выбирает
`FOREST_DENSITY_PER_HA_BY_LEAF_TYPE`:

| `leaf_type` | Плотность, дер./га |
| --- | --- |
| `needleleaved` (хвойный) | 500 |
| `mixed` (смешанный) | 400 |
| `broadleaved` (лиственный) | 350 |

Типовые иллюстративные значения (хвойный лес обычно гуще смешанного/
лиственного в средней полосе), не из авторитетного источника
лесоустройства — честно, тот же принцип, что и у остальных «типовых»
констант конвейера (`LANE_CROSS_SLOPE`, `WIDTH_BY_HIGHWAY_CLASS` и т.д.).
Без тега `leaf_type` — прежнее плоское значение 400/га, поведение по
умолчанию не меняется.

## Газон отдельно от леса (действие «газоны»)

До Шага 2.9 `landuse=grass` (газон) обрабатывался ТЕМ ЖЕ `scatter_forest_
trees`, что и настоящий лес — газон ошибочно получал 400 деревьев/га,
как будто он лес. Это исправлено: `scatter_forest_trees` теперь явно
ИСКЛЮЧАЕТ `landuse=grass` (и `natural=scrub`, см. ниже), а газон получил
собственный генератор `build_lawns` — плоская зелёная поверхность
(`flat_polygon_mesh`, тот же приём, что у ленты дороги/воды), без единого
дерева.

## Кустарник (действие «кустарники», `natural=scrub`)

Новый тип объекта, `natural=scrub` не собирался ДО этого шага вовсе —
добавлена ветка `style.lua` (в ту же таблицу `osm_vegetation`, что и лес/
газон — семантически «растительность», различаются по тегу). Расстановка —
тот же метод отбраковки, что и у леса (`scatter_shrubs`), но:

- НИЖЕ (`SHRUB_HEIGHT_M=1,2 м` против ~12 м у дерева);
- ГУЩЕ (`SHRUB_DENSITY_PER_HA=1500/га` против 350-500 у леса) — кустарник
  физически мельче и высаживается плотнее дерева.

Оба значения — типовые иллюстративные, честно не из авторитетного
источника. Отдельный тип объекта `ShrubPoint` (не `TreePoint`) — куст не
дерево, в Pset `Тип=куст`, а не порода.

## Скамейка (действие «скамейки», `amenity=bench`)

`amenity=bench` уже собирался в `osm_landscaping` с Шага 1.1 (точка), но
генератора геометрии не было. `build_benches` (`geometry.landscaping`,
тот же модуль, что и ограждения/фонари Шага 2.8) — упрощённый плоский
короб типовых габаритов (1,5×0,5×0,45 м), БЕЗ ориентации: OSM почти никогда
не даёт направление скамейки (`direction`), честное упрощение. Собран как
`IfcFurniture` — нативный класс в обеих схемах, семантически точное
соответствие; `IfcFurnitureTypeEnum` не знает значения `BENCH` ни в одной
схеме (проверено эмпирически через ifcopenshell, тот же метод, что и у
`IfcRailingTypeEnum`/`FENCE` в Шаге 2.8) — `PredefinedType=USERDEFINED`.

## Что НЕ входит в этот проход (сознательно, честно, не обещано)

- Ориентация скамейки — всегда по осям координат.
- Дифференциация высоты дерева/плотности леса по конкретному виду
  (`species`) — только по огрублённому `leaf_type`.
- Кусты/трава как готовые детальные 3D-модели (соответствует общему
  ограничению Шага 2.8, п. 3 — готовые licensed модели не интегрированы).
- Визуальная приёмка (критерий шага по плану) — недоступна AI-сессии без
  человека.

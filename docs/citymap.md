# Публичная карта города (Шаг 2.12)

Шесть пунктов плана: (1) Planetiler → PMTiles, (2) terrain-RGB рельефа,
(3) MapLibre GL (поднятые здания, дороги по классам, ЛЭП, вода, зелень,
2D/3D), (4) слои ограничений/кадастра + карточка объекта по клику,
(5) кнопка «Построить модель участка здесь» → задача сервиса 2 (Шаг 1.3),
(6) подписи источников/лицензий. Реализация — `geo/scripts/build_citymap_
vector_tiles.sh` (п. 1), `geo/src/topology_geo/citymap/{terrain_rgb,cli}.py`
(п. 2), `geo/src/topology_geo/web/citymap/index.html` (п. 3, 5, 6),
`api/app.py` (монтирование `/citymap`, `/citymap-data`).

## 1. Векторные тайлы OSM в PMTiles (Planetiler)

`geo/scripts/build_citymap_vector_tiles.sh path/to/area.osm.pbf
path/to/output.pmtiles` — обёртка над `planetiler.jar` (скачивается
отдельно, см. комментарий в самом скрипте) со встроенным профилем
OpenMapTiles: открытая, широко используемая схема слоёв (`building`,
`transportation`, `transportation_name`, `water`, `landcover`, `place`,
`poi`, `housenumber` и т.д.), которую понимает большинство публичных
OSM-карт — свой Java-профиль не написан, потому что критерий шага
(поднятые здания, стили дорог по классам, вода, зелень) уже покрывается
готовыми слоями этой схемы.

**Реально проверено**, а не заявлено: реальный `first_point.osm`
(2.1 МБ, честный `GET api.openstreetmap.org/api/0.6/map` по bbox «первой
точки» проекта — см. `docs/dev-tree.md`/историю сессий) сконвертирован в
`.osm.pbf` через `osmium cat` (Planetiler не читает XML напрямую — падает
с `Header longer than 64 KiB`, если попытаться) и реально собран в PMTiles:
архив 92 КБ, 304 КБ фич, 4377 объектов, слои `landcover`/`place`/
`transportation_name`/`building` (7.5k)/`housenumber` (5.8k)/`poi` (4.5k)
+ стандартные `water`/`transportation`. Planetiler сам печатает требование
лицензии при сборке:

```
© OpenMapTiles © OpenStreetMap contributors
```

скрипт и результат воспроизведены дважды (сначала вручную, затем самим
скриптом `build_citymap_vector_tiles.sh` end-to-end) — оба раза успешно, с
одинаковым результатом. Файл зафиксирован как тестовая фикстура
(`geo/tests/fixtures/citymap/perm_demo.pmtiles`).

**Честно не сделано:** «еженедельная пересборка» (регулярный автоматический
запуск для всего города) НЕ настроена. Причина — не код: сетевая политика
этой среды разработки блокирует и Overpass (все три независимых зеркала:
overpass-api.de, overpass.kumi.systems, overpass.openstreetmap.ru —
`ws_closed_mid_exchange` при попытке запроса), и `download.geofabrik.de`
(сброс соединения) — оба варианта регулярной выгрузки OSM-края целиком
недоступны отсюда. Сам скрипт при этом НЕ привязан к конкретному источнику
и отработает на любом реальном `.osm.pbf` без изменений там, где сеть есть
(например, в проде — с прямым доступом к Geofabrik, или через собственное
периодическое Overpass-зеркало); добавить cron/celery-beat вокруг него —
тривиально, но проверить такой прогон честно нельзя, не делая вид, что
город целиком выгружен.

## 2. Тайлы рельефа terrain-RGB

`geo/src/topology_geo/citymap/terrain_rgb.py` — кодировка Mapbox
Terrain-RGB, общепринятый формат (не придуман для проекта):
`height = -10000 + (R·65536 + G·256 + B) × 0.1` м, шаг 0.1 м, диапазон
примерно -10000…+6553.5 м — тот же формат, что понимает `raster-dem`
источник MapLibre GL (`encoding: "mapbox"`). Схема тайлов — стандартная
XYZ/slippy-map в Web Mercator, расчёт границ по стандартной формуле без
дополнительной зависимости (`rasterio`/GDAL, уже в проекте, достаточно для
репроекции и записи PNG).

`geo/src/topology_geo/citymap/cli.py` (`build_terrain_tile_pyramid`) —
берёт ЛЮБОЙ GeoTIFF (произвольная исходная CRS) и строит пирамиду
`{z}/{x}/{y}.png` для диапазона zoom/bbox. Реально проверено на настоящем
DEM: `srtm30m_first_point.tif` (2209 точек, реальный SRTM30m через
`api.opentopodata.org`, диапазон высот 94–162 м, тот же грид, что и в
прогоне «первой точки») — построенные тайлы декодируются обратно в высоту,
максимум совпал с исходным реальным замером (162.0 м).

**Честно не сделано:** источник — TessaDEM (по плану) в этой среде
недоступен (тот же блок сети, что и Geofabrik/Overpass — TessaDEM отдаётся
через похожие потоковые API). Использован `api.opentopodata.org`
(реально доступен, реальные данные SRTM30m) для точечных прогонов — не
городское покрытие целиком. CLI не завязан на источник: тот же вызов
сработает и с реальным TessaDEM-растром, если он окажется доступен по
сети (см. `docs/environment` про сетевую политику).

## 3. MapLibre GL: рендер, стили, 2D/3D

`geo/src/topology_geo/web/citymap/index.html`. Библиотеки вендорятся (как
`web/viewer/vendor/three.module.min.js` в Шаге 1.9): `vendor/maplibre-gl.
{js,css}`, `vendor/pmtiles.js` + реальные лицензии (`MAPLIBRE_LICENSE`,
`PMTILES_LICENSE`, обе BSD-3-Clause).

- **PMTiles без отдельного тайл-сервера.** `pmtiles.Protocol` регистрируется
  у MapLibre (`maplibregl.addProtocol("pmtiles", ...)`) — архив читается
  прямо из браузера диапазонными (`Range`) HTTP-запросами; сервер должен
  лишь уметь их отдавать (`206 Partial Content`) — Starlette `FileResponse`
  (`StaticFiles`, уже используется для `/viewer`) это умеет из коробки,
  реально проверено (`test_citymap_api.py::test_citymap_data_serves_real_
  pmtiles_with_range_support`).
- **Поднятые здания** — слой `building-3d` (`fill-extrusion`), высота из
  РЕАЛЬНЫХ полей схемы OpenMapTiles `render_height`/`render_min_height`
  (Planetiler сам считает их из тегов OSM `height`/`building:levels` —
  не выдуманы для этой карты), с плоским `fill`-вариантом (`building-2d`)
  для 2D-режима.
- **Дороги по классам** — цвет/ширина зависят от `class` (поле схемы
  OpenMapTiles: `motorway`/`trunk`, `primary`/`secondary`, `tertiary`/
  `residential`, пешеходные и т.д.), не одно правило на все дороги.
- **Вода/зелень** — слои `water`/`landcover` схемы, отдельные цвета по
  `class` для леса/травы.
- **2D/3D переключатель** — кнопки `#btn-2d`/`#btn-3d`: меняют
  видимость `building-2d`↔`building-3d`, `pitch` камеры (0↔45°) и
  `map.setTerrain(...)` (рельеф включён/выключен).
- **Клик по объекту** — `queryRenderedFeatures` в точке клика по слоям
  зданий/дорог/воды, всплывающее окно со всеми непустыми свойствами фичи.

**Честно не сделано:** ЛЭП (пункт 3 плана) — стандартная схема OpenMapTiles
(и, соответственно, встроенный профиль Planetiler, см. §1) НЕ включает
отдельный слой для линий электропередач — это не пропуск при стилизации,
а ограничение самой открытой схемы слоёв, которую было решено
переиспользовать вместо написания своего Java-профиля (см. §1: критерий
шага для остальных типов объектов уже закрыт готовыми слоями). Добавить
слой ЛЭП возможно только написав свой профиль Planetiler поверх тегов
`power=line`/`power=tower` — не сделано в этом проходе.

## 4. Слои ограничений/кадастра, карточка объекта

Клик-карточка (всплывающее окно свойств) реализована для всех объектов
векторной схемы (§3). **Честно не сделано:** отдельные слои
ограничений/кадастра — по плану их источник (Этап 3, кадастровые/
градостроительные данные) ещё не реализован в проекте (Этап 3 не начат),
добавлять для них пустые слои-заглушки не стали.

## 5. Кнопка «Построить модель участка здесь»

Правый клик по карте выбирает точку (`contextmenu`, маркер), поле радиуса
(500–3000 м, та же граница, что у `schemas.JobCreateRequest`), кнопка
отправляет `POST /jobs` с `{center: {lon, lat}, radius_m, layers: [],
detail: "LOD1"}` — тот же эндпоинт сервиса 2 (Шаг 1.3), без отдельного
API. После постановки — опрос `GET /jobs/{id}` раз в 2 с, по готовности —
запрос `GET /models/{id}/files` и ссылка на первый файл с `viewer_url`
(тот же вьюер Шагов 1.9/2.11).

## 6. Источники и лицензии

Видимый текст на странице (`#attribution-text`) + `AttributionControl`
MapLibre: `© OpenMapTiles © OpenStreetMap contributors` (то же требование,
что печатает Planetiler при сборке, §1), рельеф — SRTM/OpenTopoData,
библиотеки — MapLibre GL JS / PMTiles.

## Монтирование в API

`api/app.py`: `/citymap` — статика страницы+vendor (аналог `/viewer`,
Шаг 1.9). `/citymap-data` — общегородские артефакты (`city.pmtiles` +
пирамида `terrain/{z}/{x}/{y}.png`), путь задаётся `CITYMAP_DATA_DIR`
(тот же приём, что `TOPOLOGY_STORAGE_ROOT` у `tasks.pipeline_tasks.
get_storage`) — они не привязаны к конкретной задаче, в отличие от
`/models/{job}/...`. Без переменной каталог не монтируется, `/citymap-data/*`
честно отдаёт 404, а не падает при старте — реальная городская выгрузка
в этой среде не построена (см. §1/§2).

## Проверка (`docs/plan.md`)

- «Карта открывается ≤ 3 с»: проверено headless Chromium/Playwright
  (`test_citymap_browser.py::test_citymap_loads_within_three_seconds`) —
  измеряется готовность карты (`load`-событие MapLibre), не кадр рендера
  на реальном устройстве/сети — тот же честный компромисс, что и в Шагах
  1.9/2.11.
- «Выдерживает 50 одновременных пользователей»: проверено реальным HTTP —
  настоящий `uvicorn` на TCP-сокете (не in-process ASGI-транспорт), 50
  потоков одновременно шлют Range-запросы к `city.pmtiles`
  (`test_citymap_api.py::test_citymap_data_withstands_50_concurrent_
  range_clients`) — честно измерено только в этой среде (без реальной сети
  между клиентом и сервером), не заявление о production-пропускной
  способности.

## Что не входит в этот проход (честно)

- Автоматическая еженедельная пересборка PMTiles всего города (сеть
  Geofabrik/Overpass заблокирована в этой среде, §1).
- Реальное городское покрытие PMTiles/terrain-RGB (только небольшой
  реальный демо-участок ~1 км² вокруг «первой точки» построен и
  протестирован).
- Слой ЛЭП (нет в стандартной схеме OpenMapTiles/встроенном профиле
  Planetiler, §3).
- Слои ограничений/кадастра (данные Этапа 3 ещё не существуют, §4).
- Источник terrain-RGB — TessaDEM конкретно (использован
  `api.opentopodata.org`/SRTM30m, CLI источник-агностичен, §2).

# Итоговый чек-лист приёмки (Шаг 5.5)

**Это структура чек-листа, а не сама приёмка.** По плану (Шаг 5.5):
«проверка всех критериев раздела 14 основного ТЗ и этапов 0–4, подписание
акта, передача кода, документации и доступов» — работа руководителя
проекта (РП), а не автоматическая проверка. AI-сессия не может подписать
акт и не может подтвердить критерии, которые по своей природе требуют
человека (визуальная приёмка BIM-специалистом, сравнение с ручной
работой, решение о готовности) — эта таблица только собирает все критерии
плана в одном месте и указывает, где в репозитории смотреть текущее
состояние, чтобы РП не пришлось листать `docs/plan.md` и пять
acceptance-документов одновременно.

Колонка «Подтверждено» — пустая: заполняется человеком (РП или
уполномоченным им лицом) при реальной приёмке, с датой и подписью/ФИО.
Статус в третьей колонке — ссылка на актуальный источник правды
(`docs/dev-tree.md`, `docs/stageN-acceptance.md`) на момент написания
этого документа; при возврате к приёмке сверяться с этими файлами заново
(они обновляются в каждом коммите, этот чек-лист — нет).

## Как пользоваться этим документом

1. Перед приёмкой — свериться с `docs/dev-tree.md` (актуальный статус
   каждого шага может измениться после написания этого чек-листа).
2. Для шагов с ⛔/🔧 — оценить, обязательны ли они для запуска в
   эксплуатацию именно этого пилота, или могут быть перенесены в план
   развития (`docs/operations-policy.md`, раздел 3).
3. Заполнить колонку «Подтверждено» по мере реальной проверки.
4. Итоговое решение о приёмке — не автоматическое: РП принимает его на
   основе заполненной таблицы, а не наоборот.
